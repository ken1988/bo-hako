# 次期箱庭諸国 UI 再設計案（再検討版）

## 1. 前提と判断材料

本書は、ユーザーから提供された 2025 年 8 月の ChatGPT 会話ログと、2026 年 7 月時点の現行実装を突き合わせた再検討案である。当時の提案の中心は、テーブル中心の画面を単にカードへ置換することではなく、**資源のゲーム上の事実（Domain）とカード固有の見せ方（Presentation）を分離すること**だった。

現行コードから確認できる方向性は次のとおり。

- 既存 HTML を維持しながら、暖色系のデザイントークン、カード、レスポンシブ表示を導入している。
- 資源カードを描画する partial と、Domain / UI の設定ファイルがすでに追加されている。
- 所有国画面は `layout-top / left / map / right` に分割されているものの、画面上の情報優先度と操作の流れは明示されていない。
- グローバルナビゲーションは 9 項目が同じ強さで並び、日常操作と管理・外部リンクが混在している。

### 1.1 2025 年 8 月案の要点

| 当時の提案 | 意図 | 再検討結果 |
|---|---|---|
| 資源定義を Single Source of Truth にする | 追加漏れと画面間の不整合を防ぐ | **継承。最優先で完成させる** |
| `resources.domain.php` に ID、ラベル、単位、上限、format を置く | ゲーム上の事実を UI から独立させる | **修正して継承。** ラベルや単位が真に Domain かは将来 i18n 時に再分離する |
| `resources.ui.php` に順序、閾値、アイコン、密度を置く | 見た目の変更がゲームルールへ波及しないようにする | **継承。** テーマ別上書きを許容する |
| `layout-left.php` が設定をマージして partial へ渡す | 既存構造を壊さない段階導入 | **継承。** ただしマージ処理を関数化しテスト対象にする |
| テーブル表示も同じ Domain 定義へ移行する | 複数画面で定義を再利用する | **継承。** カード化より先にデータ重複を解消する |
| ラベル・単位を将来 i18n へ移す | 表示文言を Domain から分離する | **保留。** SSOT 完成後に行う |

### 1.2 現行実装との差分と問題

- `resources.domain.php` と `resources.ui.php` は存在するが、`layout-left.php` はそれらを読み込まず、資源配列を再度直書きしている。このため、現時点では SSOT が成立していない。
- Domain 定義には 13 資源（ウランを含む）がある一方、UI の `order` と `layout-left.php` はウランを含まない。追加資源の表示漏れが、当時防ごうとしていた形で実際に発生している。
- `resources.domain.php` は関数内で `var` を使用しており、現行 PHP では構文エラーになる。さらに `$init` を受け取る設計にもかかわらず、単位と上限をファイル内に再定義している。
- `resources.ui.php` の warn / bad 閾値はカード描画側へ渡されず、partial には 75% / 90% が直書きされている。
- `layout-left.php` と Domain のラベルが一致していない項目があり、`alcohol` は「酒」と「肉」に分岐している。どちらが正しいゲーム仕様か決定が必要である。

したがって、次の実装ではカードの装飾追加より先に、**設定ファイルを実際の表示経路へ接続し、重複定義をなくす**必要がある。

## 2. 再検討後の設計方針

### 2.1 「装飾の刷新」から「判断と実行の短縮」へ

プレイヤーの主要サイクルを **状況把握 → マップ確認 → コマンド投入 → 結果確認** と定義する。色やカード表現だけでなく、この順番が視線移動と画面遷移に反映されることを最優先にする。

### 2.2 情報を 3 層に整理する

1. **常時表示:** 国名、ターン、次回更新、主要資源、警告、未実行コマンド数。
2. **作業中に表示:** マップ、選択座標、コマンドパレット、コマンドキュー。
3. **必要時に表示:** 全資源、国勢詳細、収支内訳、ログ、掲示板、設定。

デスクトップでは 3 カラム、タブレット以下では 1 カラムにし、モバイルでは「概要 / マップ / 計画 / ログ」の下部タブで作業文脈を保つ。

### 2.3 色に意味を持たせる

- ブランド色（橙）: 主操作、選択中、現在地。
- 成功（緑）: 増加、実行可能、安全。
- 注意（黄）: 容量逼迫、更新前、確認が必要。
- 危険（赤）: 不足、災害、破壊的操作。
- 中立（灰）: 補助情報、無効状態。

状態を色だけで伝えず、アイコン・ラベル・数値を併記する。本文と背景は WCAG 2.2 AA のコントラストを目標にする。

### 2.4 既存資産を段階移行する

ゲーム固有のマップチップは維持する。一方、ナビゲーションアイコン、余白、文字サイズ、ボタン状態は共通コンポーネントに寄せる。PHP の全面改修を先行させず、出力データと表示を少しずつ分離する。

## 3. 画面イメージ

実装可能性を確認するためのスタンドアロンモックを `docs/ui-mockup/index.html` に用意した。これは当時依頼された「新しい UI」と「スマホ対応 UI」の画面イメージを、資源カードだけ孤立させず所有国画面全体の中で再検討したものだ。実データの保存やコマンド実行は行わない。

### デスクトップ

`docs/ui-mockup/index.html` を幅 1024px 以上で開くと、3カラムのデスクトップ案を確認できる。

- 上段で更新時刻、ターン、緊急通知、主要資源を一読できる。
- 中央のマップを最大の作業領域とし、座標選択後の操作を右のパレットへ連続させる。
- コマンドキューには実行順・対象・費用を表示し、並べ替えと取り消しの場所を固定する。

### モバイル

`docs/ui-mockup/index.html` を幅 800px 以下で開くと、1カラムと下部ナビゲーションのモバイル案を確認できる。

- 主要指標と警告を先に表示し、マップは横スクロールではなく表示領域内へ縮小する。
- 頻繁に使う 4 文脈を下部ナビゲーションに固定する。
- タップ領域は最低 44px を目標にし、詳細な表はカードまたは開閉式表示へ変換する。

## 4. 画面・コンポーネント仕様

| 領域 | 目的 | 主要要素 | モバイルでの扱い |
|---|---|---|---|
| アプリヘッダー | 現在位置と主要導線 | ロゴ、国名、ターン、通知、ユーザーメニュー | 国名と通知を残し、他はメニューへ |
| ステータス帯 | 即時判断 | 次回更新、人口、資金、食料、重要警告 | 2 列カード、詳細は展開 |
| 国勢サイドバー | 中期判断 | 支持率、産業、外交、軍事、収支 | 「概要」タブ内に統合 |
| マップ | 対象選択 | 地形、座標、ズーム、凡例、選択状態 | 幅に合わせて縮小、拡大モーダルを用意 |
| コマンドパレット | 行動選択 | カテゴリ、検索、費用、実行可否 | 「計画」タブで全幅表示 |
| コマンドキュー | 計画確認 | 順番、対象、費用、編集、取消 | 1 件 1 カードで表示 |
| イベントログ | 結果確認 | 重要度、ターン、対象リンク | 「ログ」タブ、未読数を表示 |

## 6. 受け入れ基準（最初のリリース）

- 360px 幅でページ全体の意図しない横スクロールが発生しない。
- ログイン後、主要資源・次回更新・警告をスクロールせず確認できる。
- マップ上の座標選択からコマンドキュー追加まで、画面遷移なしで完了できる。
- すべての操作要素がキーボードで到達・実行でき、フォーカス位置を視認できる。
- 破壊的操作には対象と影響を明記した確認があり、通常操作と見分けられる。
- 既存の国家データ、コマンド処理、ターン処理を変更せずに新旧表示を切り替えられる。
